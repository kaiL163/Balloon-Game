# Математическая модель Crash

## Crash point

До старта раунда сервер создаёт секретный `serverSeed` и публикует его SHA-256 hash.
После получения ID раунда вычисляется:

```text
hash = SHA-256(serverSeed + ":" + roundId)
u = first52Bits(hash) / 2^52
crash = floor(100 * clamp((1 - houseEdge) / (1 - u), min, max)) / 100
```

При `houseEdge = 0.03` теоретический RTP равен 97%, а вероятность дожить до
коэффициента `x` приблизительно равна `0.97 / x`.

Примеры:

| Событие | Вероятность |
| --- | ---: |
| Мгновенный crash около 1.00x | 3% |
| Дойти до 1.50x | 64.7% |
| Дойти до 2.00x | 48.5% |
| Дойти до 5.00x | 19.4% |
| Дойти до 10.00x | 9.7% |

`minMultiplier` не должен быть выше `1.00`: иначе все значения нижнего хвоста
склеиваются в одну часто повторяющуюся точку. После расчёта действует предел темы:
`10.00x` для зелёного шара и `25.00x` для красного. Эти значения можно изменить
в панели администратора.

Уровни распределены по логарифмической шкале:

```text
level = floor(levelCount * ln(multiplier) / ln(themeMaxMultiplier))
```

Поэтому 9-й уровень зелёного маршрута соответствует его пределу `10x`, а
12-й уровень красного — пределу `25x`.

## Рост коэффициента

Во время полёта применяется экспоненциальная кривая:

```text
multiplier(t) = exp(growthRate * t)
```

При начальном `growthRate = 0.12` коэффициент достигает 1.50x примерно за 3.4 секунды,
2.00x за 5.8 секунды и 5.00x за 13.4 секунды. Backend пересчитывает значение
каждые 100 мс и остаётся единственным источником игрового результата. Скорость
также изменяется из панели администратора.

## Выплата

```text
win = betAmount * multiplierAtCashout
```

Cashout и серверный tick выполняются под блокировкой одного раунда. Поэтому при
одновременном cashout и crash результат определяется одной атомарной операцией.

## Управляемая конфигурация

Конфигурация версии хранится в таблице `game_settings` и редактируется через
защищённую страницу `/admin`. После сохранения backend проверяет значения,
обновляет запись и атомарно заменяет кэш настроек. Перезапуск приложения не нужен.

| Группа | Параметры | Допустимые значения |
| --- | --- | --- |
| Базовые | `game_id`, `game_name`, `game_type`, `is_active` | непустые ID/название; тип `CRASH`; active включает новые раунды |
| Crash | `crash_distribution`, `house_edge`, `min_crash_multiplier` | `INVERSE_RTP`; 0–0.25; 1.00–2.00x |
| Ограничения | `green_max_multiplier`, `red_max_multiplier` | 1.01–100x и не ниже минимального crash |
| Динамика | `multiplier_growth_rate`, `fps`, `delta` | 0.03–0.50; 1–60 FPS; `delta = 1 / fps` |
| Позиция бустера | 9 весов GREEN и 12 весов RED | каждый 0–1; хотя бы один вес темы больше нуля |
| Бустеры | `multiplier_tier_1_value` … `tier_4` | 1.00–10.00x |
| Ставки | `bet_tier_1_amount` … `bet_tier_4_amount` | 1.00–1000000.00 бонусов |
| Очки | `points_per_line`, `points_cashout_bonus`, `points_xn_bonus` | целые числа 0–100000 |

Позиция бустера выбирается независимо от crash по нормализованным весам линий.
Если шар лопнул раньше нужной линии, бустер считается пропущенным. Начисление за
линии рассчитывается как `число фактически пройденных линий × points_per_line`,
поэтому результат остаётся корректным даже при низком FPS или быстром росте.
